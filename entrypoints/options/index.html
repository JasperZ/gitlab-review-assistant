Rule syntax

Both columns are globs. * matches within one path segment; ** crosses / and also matches zero segments, so **/templates/*.yaml matches templates/a.yaml at the repo root as well as charts/app/templates/a.yaml.

  • Project matches the full path, e.g. mygroup/subgroup/service. Use ** for every project. Matched case-insensitively.
  • File paths take one glob per line; a file is marked if it matches any of them. Paths are relative to the repository root and matched case-sensitively. A leading / is not a repo-root anchor — it is ignored.
  • Lines starting with # are notes, not globs, so you can group and label entries. They are saved with the rule.
  • Brace sets work: **/*.{yaml,yml}.

What is never marked

Files GitLab shows no Viewed checkbox for are always skipped — there is nothing to tick. Everything else is governed by the boxes at the top of this page.

Marking never un-ticks anything, and files you already reviewed by hand are left untouched. The one exception is Unmark all in the confirmation dialog, which clears every tick in a merge request and asks twice first.
